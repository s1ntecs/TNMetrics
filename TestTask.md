### Цель

Создать простой REST
API для управления метриками с минимальным набором функций и настроенной админ
панелью.

### Бизнес-логика

Система состоит из **Метрик (Metric)** и связанных с ними  **Записей Метрик (MetricRecord)** . Каждой
записи можно проставлять  **тэги (Tag)** .

Метрики представляют собой абстрактные показатели (например, трафик, продажи,
температура), а записи содержат значение показателя и временную отметку, что
позволяет строить графики изменений во времени.

У всех пользователей свои метрики и записи, тэги общие и создаются через админ
панель.

### Модели

·
 **Metric,
MetricRecord, Tag** ,

·
набор полей
минимально необходимый для работы с показателями и их временными значениями.

### Требования

·
Приложение
должно запускаться в docker-compose

·
База данных
PostgreSQL

·
Redis (кэш,
брокер Celery)

·
Простая JWT
авторизация

·
Настроено
создание суперпользователя, а затем добавление пользователей через админ панель

·
Настроить
кэширование списка записей метрик в метрике, при добавлении записи
инвалидировать кэш

·
Настроить Celery
Beat задачу, которая создает «фейк отчет». В отдельной директории в корне
проекта создает, а затем обновляет текстовый файл раз в 2 минуты с содержанием
общего количества метрик и записей в базе данных.

·
Настроить админ
панель для управления Metric, MetricRecord, Tag

·
Эндпоинт на
создание записи метрики покрыт тестами

### Эндпоинты

·
**POST /api/token/** — получение JWT токена

·
**POST /api/metrics/** — создание метрики (требуется авторизация)

·
**GET /api/metrics/** — список метрик пользователя (требуется
авторизация)

·
**GET /api/tags/** — Получить список тэгов (требуется авторизация)

·
**GET
/api/metrics/{id}/records/**
— список записей конкретной метрики

(должен кэшироваться, требуется авторизация)

·
**GET
/api/metrics/{id}/records/{id}**
— Детализация одной записи метрики (требуется авторизация)

·
**POST
/api/metrics/{id}/records/**
— создание записи метрики

(требуется авторизация, покрыт тестами)
